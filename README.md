# DAEGU FOOD BIZ v0.7 — 144개 지역 데이터 반영판

기존 v0.6 및 최초 v0.3의 흑백 미니멀 디자인을 유지하면서 2026-11-25 갱신 전달 파일 `frontend_handoff (1).zip`의 실제 데이터에 맞춰 수정했습니다.

## 1. 가장 빨리 화면 확인하는 방법 (Mac, 터미널 불필요)

1. 전체 ZIP 파일 압축 해제.
2. 폴더 안의 `preview_quick_open.html`을 **더블클릭**하여 브라우저에서 열기.
3. `담당자용` → `구·군 선택`에서 `달성군` 또는 `군위군` 선택.
4. `지도 레이어`를 `3년 점포 증감 · 현황(예측 아님)`으로 바꾸면 해당 읍·면의 과거 현황을 확인할 수 있습니다.

이 HTML은 **인터넷 없는 단독 미리보기**입니다. 실제 데이터가 HTML에 포함되어 있지만 PostgreSQL·Gemini API 호출은 없습니다. 개인 Mac에서 Chrome 또는 Safari로 열어 확인합니다.

## 2. 이번 갱신 파일에 실제로 들어 있는 데이터

| 대상 | 수 | 표시 |
| --- | ---: | --- |
| 7개 구 법정동 | 130 | 65곳 정체 동의 병목 진단 + 65곳 비정체 동 현황 |
| 정체 동 | 65 | 진입 병목 31 / 생존 병목 34, 확신도 높음·보통·낮음 |
| 달성군 읍·면 | 9 | 과거 점포 현황과 카페 생존율·연도별 개·폐업 **전용** |
| 군위군 읍·면 | 5 | 과거 점포 현황과 카페 생존율·연도별 개·폐업 **전용** |
| 전체 지역 | 144 | 담당자 현황 / 창업자 카페 데이터 |
| 전달된 행정동 경계 | 150 | 7개 구 133, 달성군 9, 군위군 8 (자료 없는 군위군 3개 면은 지도에서 자료 미제공) |

달성군·군위군은 서울의 '동' 단위와 성격이 다른 읍·면이므로 **기존 예측 모델의 검증 범위 밖**입니다. 병목 분류·모델 확신도를 계산하거나 채워 넣지 않습니다. `is_stagnant`, `bottleneck`, `confidence` 등의 빈칸은 데이터 누락 오류가 아니라 **의도된 진단 제외**입니다. 군위군의 인구 3년 증감값 `pop3`도 제공되지 않아 '—'로 표시합니다.

- 실제 경계는 아직 **행정동 GeoJSON**입니다. 7개 구 법정동 색칠은 임시로 대응시킨 대표 행정동 폴리곤이므로 법정동의 정확한 공간적 진단으로 해석하지 않습니다.
- 달성군·군위군은 전달된 행정동 경계에서 면·읍이 실제 존재하지만, 이 14개도 **현황만** 보여 줍니다.
- 개업 후 2년 생존율은 과거 카페·디저트 자료(표본 부족 보정)이며 매출이나 개별 점포 성공을 예측하는 값이 아닙니다.

## 3. UI 수정사항

- **기존 첫 화면 보존.** 검정 삼각형·그라데이션·지도 별자리 그림을 추가하지 않았습니다.
- 홈으로 되돌아갈 때도 기존 부드러운 인트로 애니메이션이 재생되도록 수정했습니다.
- 상단 네비게이션의 `DAEGU FOOD BIZ · 2025 BASELINE · V2 MODEL` 문구 삭제. `처음으로 / 담당자용 / 창업자용`과 활성 메뉴 강조는 유지.
- 담당자용 선택기: `지도 레이어 / 구·군 / 법정동·읍면` **한 행**으로 정렬(좁은 화면에서는 자동 줄바꿈).
- 창업자용 제목 `업종별 동 분석`과 작은 설명을 한 행에 배치(모바일은 줄바꿈).
- 사진 속 상대 순위의 **진입 활력 / 생존 안정 막대 모두 차분한 녹색 계열**로 변경. 지도 병목 파랑·주황은 변경 없음.
- 창업자용 연도별 개업/폐업 막대는 **초록/빨강**으로 구별. 범례와 마우스 올리기 숫자 유지.
- 기존 v0.6의 `+/-` 줌 버튼, 마우스 중심 확대, 구·군 선택 시 해당 지역만 표시, 지도 이동 경계, 초기화 버튼, 우측 상단 고정 정보창(지역 / 지역코드 / 분석) 유지.
- 지도 범례에 별도 회색 `진단 범위 밖 · 현황만(읍·면)`을 추가하여 7개 구의 `정체 동 아님`과 구별.

## 4. 보고서·정책·무료 API

- **진입 병목 리포트 필수 문구:** 안정적 기존 점포 구조인지 수요 감소에 따른 침체인지 모델로 구분할 수 없으므로, **실무 담당자의 현장 조사 필수**. 지원사업 데이터가 있어도 삭제할 수 없도록 앱의 생성 후 검증 규칙을 추가했습니다.
- 실제 지원사업 목록 데이터는 아직 받지 못했습니다. 사업명·자격·기간을 추정하지 않습니다.
- `llm/report_input_example.json`의 두 리포트 예시는 **프로젝트 자료에서 제공한 예시**입니다. 지원사업 DB는 별도로 미연결 상태입니다.
- 비용이 드는 OpenAI API 호출 코드 대신 **선택적 Google Gemini API**(기본 모델 `gemini-2.5-flash-lite`) 연결 코드를 준비했습니다. `GEMINI_API_KEY`가 없는 경우 **API를 호출하지 않고 템플릿**을 보여 줍니다. 이 버전에서는 실제 외부 LLM 호출·품질 검증을 진행하지 않았습니다.
- Gemini는 무료 요금제의 프로젝트와 사용량 제한을 직접 확인해야 합니다. Google 프로젝트에서 유료 과금 설정을 사용하면 비용이 발생할 수 있으므로 **이 앱 자체가 절대 과금되지 않는다고 보장하지는 않습니다**. API 키를 Git에 올리지 마세요.
- HTML 보고서 미리보기에는 **인쇄 / PDF로 저장** 버튼을 넣었습니다(브라우저의 인쇄 창 사용). 정식 Streamlit 보고서의 별도 PDF 생성기는 추후 구현 대상입니다.

## 5. Streamlit 앱 실행 (Mac)

Python 3.10+ 설치 후, 압축을 푼 프로젝트 폴더에서:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

웹브라우저 `http://localhost:8501` 열기. 이 프로젝트에는 실제 인터넷 주소로 배포된 Streamlit 서비스가 **아직 없습니다**. 사용자가 원하는 URL 한 번 클릭 방식은 Streamlit Cloud 등 별도 배포를 완료해야 합니다.

## 6. PostgreSQL 학습용 구축

외부 PostgreSQL 서버는 생성하지 않았습니다. 스키마/적재 도구만 준비한 상태입니다.

1. PostgreSQL 14+ 설치, 예를 들어 `daegu_food_biz` 데이터베이스를 생성합니다.
2. 원본 파일 검사: `python scripts/sync_data.py --check` → `144 / 정체 65 / 진단 범위 밖 14 / 카페 144 / 맵 매핑 328`이 출력됩니다.
3. `DATABASE_URL='postgresql+psycopg://사용자:비밀번호@localhost:5432/daegu_food_biz'`를 로컬 환경변수로 설정합니다.
4. `python scripts/sync_data.py --apply`로 한 트랜잭션에 원본 버전 이력(`raw`)과 최신 마트(`mart`)를 적재합니다.
5. `SELECT diagnosis_scope, COUNT(*) FROM mart.officer_latest GROUP BY diagnosis_scope;`로 세 분류가 65/65/14인지 확인합니다.
6. `python scripts/sync_data.py --watch --interval 300`은 현재 PC가 켜져 있을 때만 파일 변경을 감시합니다. 클라우드 예약 자동화는 별도 배포 단계에서 구성합니다.

새 데이터의 `diagnosis_scope` 컬럼과 읍·면의 `is_stagnant=NULL`을 반영하기 위해 `db/schema.sql`에서 스키마를 변경했고, 기존 DB에도 적용할 수 있는 `ALTER TABLE` 명령을 포함했습니다.
