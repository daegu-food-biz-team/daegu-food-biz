# LLM 진단 리포트 작성 규칙

리포트는 `report_input_example.json`과 같은 형식의 입력만 근거로 씁니다. 입력에 없는 숫자, 사업명, 원인은 만들지 않습니다.

## 프롬프트에 넣을 규칙

1. 입력 JSON에 있는 값만 사용한다. 없는 수치나 사업은 쓰지 않는다.
2. 진단은 "대구 정체 동 65곳과 비교한 상대 평가"라고 밝힌다.
3. 확신도와 과거 적중률(`past_accuracy`)을 반드시 같이 쓴다.
4. `rule_agree`가 false이면 "단순 지표와 방향이 달라 현장 확인을 먼저 권한다"고 쓴다.
5. 지원 유형은 "먼저 검토할 후보"로 쓴다. "해야 한다"고 쓰지 않는다.
6. `support_programs`가 비어 있으면 "[연결 예정] 지원사업 DB 연결 후 표시"라고 쓴다.
7. 마지막에 한계 문단을 넣는다: 외식 점포 인허가 기준, 매출 예측 아님, 지원 우선순위 판단 안 함.

## 쓰면 안 되는 표현

| 금지 | 대신 |
| --- | --- |
| 매출이 오를/떨어질 동 | 외식 점포가 늘/줄 가능성 |
| 상권이 살아날/죽을 동 | 진입 병목 / 생존 병목 |
| 지원이 시급한 동, 우선 지원 대상 | (쓰지 않음. 우선순위는 모델이 판단하지 않음) |
| AI가 예측한 확률 70% | 과거 같은 확신도 구간에서 70%가 맞았음 |
| 처방, 해결책 | 먼저 검토할 지원 유형 |
| (창업자용) 여기 창업하지 마세요 | 과거 이 동 카페의 2년 생존율은 대구 평균보다 낮았음 |

## 리포트 구조 (담당자용)

1. 진단 카드: 병목 유형, 확신도(과거 적중률), 단순 지표 일치 여부
2. 요약: 3~4문장
3. 근거 숫자: `status`의 값 6개 내외
4. 요인: `top_factors` 3개를 문장으로
5. 먼저 검토할 지원 유형 + 연결 사업
6. 현장에서 확인할 것: `check_on_site`
7. 한계

예시는 `report_example_동성로2가.md`와 화면 시안의 Report 화면을 보세요.

## 2026-11-25 추가 운영 원칙: 진입 병목 현장 조사 의무 권고
- 진입 병목이 나온 지역은 안정적인 기존 점포 구조와 침체로 인한 신규 진입 부족을 모델만으로 구별할 수 없습니다.
- **지원사업 데이터가 제공되어도, 제공되지 않아도 반드시 실무 담당자의 현장 조사를 선행하라고 보고서에 명시합니다.**
- 공실·임대료·업종 구성·지역 수요 등을 점검하고 정책 방향은 현장 조사 이후 검토합니다.
- 단순히 진입 병목이라는 이유로 창업을 늘리라고 권고하지 않습니다.
